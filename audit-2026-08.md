# Roam code audit — 2026-08-26

Full-codebase pass over both repos (backend `src/` + `scripts/`, frontend
`src/App.jsx` + billing pages + iOS config) at ~22 users, post-v1.5 merge.
Supersedes the July 2026 audit list that used to live in CLAUDE.md — items
fixed since then (CORS allowlist, helmet, public-endpoint column trimming,
PostgREST injection, SSRF, per-route authorization) are verified fixed and
not repeated here.

Severity is "what actually bites at current scale," not theory.

## Fix first

1. **[HIGH][backend] Case-sensitive email lookup locks users out.**
   Registration lowercases email (`src/routes/auth.js:40`) but login
   (`auth.js:58`) and forgot-password (`auth.js:144`) query with the raw
   input. Anyone typing `Bob@Gmail.com` gets "Invalid email or password" and
   a silent no-op password reset. One-line fix in each spot.
2. **[MED][backend] Paid perks survive payment failure.**
   `syncSubscription` (`src/config/supabase.js:45-47`) sets `venues.plan`
   from the Stripe price and ignores subscription `status`;
   `invoice.payment_failed` (`src/routes/webhooks.js:73-93`) keeps the paid
   tier. A failed card keeps pro/premium (boost, custom marker,
   premium deals) until `customer.subscription.deleted` fires days later.
   Grant perks only for `active`/`trialing`.
3. **[MED][frontend] `venue.website` rendered as raw `href`**
   (`App.jsx:634`): no scheme check, so a stored `javascript:` URL executes
   in-app on tap — and the JWT lives in localStorage, so this is the one
   real XSS→token path. Gate on `/^https?:\/\//i` (same for
   `p.attribution_uri` at `App.jsx:602`; `instagram` at `:636` is
   link-spoofing only).
4. **[MED][backend] 1000-row PostgREST truncation on list endpoints.**
   No `.limit()` + city filtering done in JS:
   - `GET /api/deals` fetches ALL active deals (`src/routes/deals.js:39`) —
     recurring deals never expire (2099 sentinel), so past 1,000 rows some
     cities silently lose deals. 357 deals today; this breaks quietly as
     scraping grows.
   - `GET /api/events` same pattern (`src/routes/events.js:102`).
   - Bounds-baseline query (`src/routes/venues.js:319`) can exceed 1,000
     `venue_typical_hours` rows on a wide viewport.
   - `monthlyCrawl` city enumeration (`src/jobs/monthlyCrawl.js:313`)
     selects `venues.city` unbounded — cities beyond row 1,000 would never
     be crawled. 2,684 venues today: likely already >1,000 with websites.
5. **[MED][frontend] Mojibake on the paid flow.** `BillingSuccess.jsx`
   (68, 74-76, 85-86) and `PricingPage.jsx` (44, 149) render corrupted
   UTF-8 ("â€¦", "âœ“") — the screen a venue owner sees right after paying.
   Re-save as UTF-8.
6. **[MED][frontend] 1.5s `pulse` state re-renders the whole map screen**
   (`App.jsx:957/983`) just to animate two marker shadows. Move to a CSS
   keyframe; biggest cheap perf win.

## Backend — remaining findings

- **[MED] Unauthenticated venue detail triggers billed Google Places
  fetches** (`venues.js:487` → `getPlaceData:428`, `/photos/:idx:595`).
  Enumerating all 2,684 venue ids re-primes the Places cache at our cost,
  gated only by 500 req/15min/IP. Consider a tighter limiter on these
  routes or negative-caching.
- **[LOW] Admin secret compared with `===`** (`middleware/adminAuth.js:6`);
  use `crypto.timingSafeEqual`. Guards claimant emails.
- **[LOW] Inline `jwt.verify` in venue detail skips `token_version`**
  (`venues.js:505,529`) — revoked tokens can still read friends-here/
  favorite state. Also: no `algorithms: ["HS256"]` pin anywhere (not
  exploitable with HS256 secret, cheap hardening).
- **[LOW] Cron jobs other than monthlyCrawl have no cross-instance claim**
  (`index.js:87-186`) — fine on single-instance Railway.
- **[LOW] Crowd-report score upsert race** (`venues.js:619-621`) —
  last-writer-wins, self-heals within 15 min.
- Hygiene: `autoScrapeDeals.js` duplicates ~100 lines of `monthlyCrawl.js`
  helpers; owner-check boilerplate copy-pasted in 8 route files; ~20 silent
  `catch` blocks with no logging (list in agent notes); candidate indexes:
  `crowd_reports(venue_id, reported_at)`,
  `analytics_events(venue_id, event_type, created_at)`,
  `friend_locations(user_id)` — verify against live schema first.

## Frontend — remaining findings

- **[LOW] Story like-state never seeded from the server**
  (`App.jsx:1539/1626/1718/1746`): already-liked stories render unliked, and
  a like + feed refetch double-counts (+1 on top of the server's new
  count). Needs an `is_liked` flag in the stories API to fix properly.
- **[LOW] Module-level map state (`mapCameraState`, `hasAutoCentered`,
  `pendingMapFocus`) not reset on logout** (`App.jsx:887-889, 3375`) —
  next login on a shared device inherits the previous user's camera.
- **[LOW] `loadFriends` 20s poll closes over `token` with `[]` deps**
  (`App.jsx:1034-1042`).
- **[PERF] Mapbox ~1.8 MB chunk loads statically even for /billing and
  /reset-password entries** — `React.lazy` the map screens when convenient.
- **[NOTE] No associated-domains entitlement** — `app.roaman.app/v/...`
  share links open the web bounce page, never the installed app. Add
  Universal Links when share volume justifies it.
- Hygiene: billing pages bypass `apiFetch` (raw fetch + own Bearer
  boilerplate); `toggleSaveDeal`/share helpers duplicated across screens;
  `setCurrentCity` fires on every map pan (re-renders app root when the
  nearest-city label flips).

## Verified clean (checked, not assumed)

Backend: PostgREST `.or()`/`.in()` interpolations (all UUID-sourced or
sanitized), SSRF guards on every user-URL fetch incl. redirect hops, Stripe
webhook signature, no PII/secret leakage in public shapes, reset/OTP token
handling, no email-header injection. Timezone/6am-anchor math consistent
across routes, analytics, and the new rollup job.

Frontend: deep-link hash parsing, img-src usage, no committed secrets, iOS
ATS intact, fetch race guards on all main screens, SplitMapView
viewport-filter feedback guards hold.
